RANK: B > A

B makes the same core move (direct upload, async resize, small bounded workers) with better judgment for two people. It authenticates the grant, re-checks stored size, uses a real status machine, writes every derivative before `ready`, and names the leftover OOM trap: a 25 MB file can decode to a huge bitmap, so pixel caps and sequential single-image work matter more than swapping libraries. Failures keep originals for retry, reject poison files, and sweep abandoned work. Tradeoffs are explicit.

A is a solid operational recipe (privacy strip, dual completion trigger, lifecycle, poll cadence) but a thinner state model, stores URLs instead of keys, and underplays decode bombs. Extra cataloging does not beat B’s constraints and consistency.
